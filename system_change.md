# Laptop migration — bringing the engine up on a new Mac

This runbook is the **single source of truth** for moving the Indian Banking
Knowledge Base engine from one Mac to another. Follow the path that matches
your situation:

- **Path A — cold rebuild (no old laptop / no data carried over).**
  You only have the git repo. Everything else (Python venv, Chromium,
  per-bank PDFs, SQLite index) is regenerated from scratch. ~1–3 hours of
  unattended backfill at the end. **This is what you'll do in most cases.**
- **Path B — warm migration (you still have the old laptop or its disk).**
  You also rsync the per-bank PDFs and the SQLite index over. Saves the
  backfill wait and the ~1–4 GB of re-download.

Both paths end at the same verification step.

> The git repo contains **only** `_engine/` — the Python code, configs, and
> scripts. The downloaded PDFs and SQLite index live in **sibling folders**
> (`KnowledgeBase/<Bank>/...` and `KnowledgeBase/_engine/kb_index.sqlite`)
> and are intentionally *not* tracked in git. They're either regenerated by
> the engine (Path A) or copied over manually (Path B).

---

## 0. Prerequisites on the new Mac

Install these once. None are project-specific.

```bash
# 1. Apple command-line tools (gives you git, clang, headers Playwright may need)
xcode-select --install

# 2. Homebrew (optional but used for everything below)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 3. Python 3.10+ (the engine needs 3.10 or newer — for `dict[str, ...]` syntax in bank_kb/)
brew install python@3.12      # or python@3.11 / python@3.13 — any 3.10+

# 4. SQLite CLI (only needed if you ever want to inspect the index by hand;
#    macOS already ships /usr/bin/sqlite3, but Homebrew's is more recent).
brew install sqlite

# 5. Cursor (optional — only if you want the same `refresh.sh` workflow from
#    Cursor's terminal). Download from cursor.com.
```

Verify:

```bash
python3 --version    # should print 3.10.x or higher
git --version
sqlite3 --version
```

## 1. Clone the repo into the right place

The engine expects to live at `<anything>/KnowledgeBase/_engine/`, with the
parent `KnowledgeBase/` folder reserved for the per-bank data folders.

You're free to put `KnowledgeBase/` wherever you want — the engine resolves
its own path via `Path(__file__).resolve().parent`. The example here uses
the same path as the old laptop, but you don't have to.

```bash
# Pick a parent location (this is just an example matching the old laptop)
mkdir -p ~/Documents/RWork/Banking_Data/KnowledgeBase
cd       ~/Documents/RWork/Banking_Data/KnowledgeBase

# Clone the engine into _engine/ (NOT into a 'KnowledgeBase-engine' folder)
git clone <your-repo-url> _engine
cd _engine
```

If you used a different parent path, **update the alias and any LaunchAgent
install paths** later in this doc accordingly.

---

## 2. Recreate the Python virtualenv + install deps

The `.venv/` folder is .gitignored (~150 MB with Playwright + Chromium) so
you build it fresh.

```bash
cd ~/Documents/RWork/Banking_Data/KnowledgeBase/_engine

python3 -m venv .venv
source .venv/bin/activate

python3 -m pip install --upgrade pip
python3 -m pip install -r requirements.txt
```

Sanity check:

```bash
python3 -c "import requests, bs4, pdfplumber, playwright; print('deps ok')"
```

---

## 3. Install Playwright's headless Chromium

This is what lets the engine drive JS-rendered IR pages (Axis year-dropdown,
HDFC, ICICI, SBI, etc.) automatically. Without it the engine still runs but
falls back to static-HTML scraping and misses anything behind a year
selector.

```bash
python3 -m playwright install chromium
```

Smoke test (should print `chromium-ok` and exit cleanly):

```bash
python3 -c "from playwright.sync_api import sync_playwright; p = sync_playwright().start(); b = p.chromium.launch(headless=True); print('chromium-ok'); b.close(); p.stop()"
```

If the first `playwright install` failed with a checksum / network error,
re-running it usually works — the installer is restart-safe and resumes.

---

## 4. Recreate the per-bank folder skeleton

`banks_config.json` *is* in the repo, so the engine knows the 20 banks
already. It just hasn't materialized their folders on the new disk yet.

```bash
python3 run.py --sync-structure
```

This creates `../HDFC_Bank/{investor_presentations,annual_reports,...}/`,
`../Axis_Bank/...`, etc. — empty folders next to `_engine/`. Costs zero
network, takes <1 second.

## 5. Populate the corpus — choose Path A or Path B

### Path A — cold rebuild (no old data carried over)

This is the default path. It pulls 5 years of history for every configured
bank and rebuilds the SQLite index from scratch.

```bash
python3 run.py --mode backfill --verbose
```

Expect:

- 500 – 1,500 PDFs total (varies with each bank's press-release verbosity)
- 1 – 4 GB of disk used in the sibling `KnowledgeBase/<Bank>/` folders
- 1 – 3 hours wall time on a residential connection (the engine sleeps 2 s
  between requests to be polite — adjust `request_delay_seconds` in
  `banks_config.json` if you have a faster pipe and want to be aggressive)

Tip: run it inside `caffeinate` so the Mac doesn't sleep mid-run:

```bash
caffeinate -is python3 run.py --mode backfill --verbose
```

Or, to pilot on one bank first before committing to the full run:

```bash
python3 run.py --mode backfill --bank Axis_Bank --verbose
```

### Path B — warm migration (data carried over from old laptop)

If you still have the old laptop (or a backup of its `KnowledgeBase/`
folder), copying the data over saves the multi-hour backfill.

**On the old Mac**, identify what to copy. Everything *under* `KnowledgeBase/`
*except* `_engine/.venv` (machine-specific) is worth migrating:

```bash
# Things to copy (sizes will vary):
#   KnowledgeBase/<every Bank>/                  ← the PDFs (~1–4 GB)
#   KnowledgeBase/_engine/kb_index.sqlite        ← FTS5 index (~100–500 MB)
#   KnowledgeBase/_engine/_logs/                 ← optional, for audit history
#
# Things to NOT copy:
#   KnowledgeBase/_engine/.venv/                 ← rebuild on the new Mac
#   KnowledgeBase/_engine/__pycache__/           ← rebuild automatically
#   KnowledgeBase/_engine/.git/                  ← `git clone` already gave you this
```

Two ways to transfer:

**Over the network (LAN, both Macs awake):**

```bash
# Run this on the NEW Mac
rsync -avh --progress --exclude='.venv' --exclude='__pycache__' --exclude='.git' \
    olduser@old-mac.local:'~/Documents/RWork/Banking_Data/KnowledgeBase/' \
    ~/Documents/RWork/Banking_Data/KnowledgeBase/
```

**Via external SSD:**

```bash
# On the OLD Mac, write to the drive
rsync -avh --progress --exclude='.venv' --exclude='__pycache__' --exclude='.git' \
    ~/Documents/RWork/Banking_Data/KnowledgeBase/ \
    /Volumes/MyDrive/KnowledgeBase-backup/

# On the NEW Mac, read from the drive
rsync -avh --progress \
    /Volumes/MyDrive/KnowledgeBase-backup/ \
    ~/Documents/RWork/Banking_Data/KnowledgeBase/
```

After the copy:

```bash
cd ~/Documents/RWork/Banking_Data/KnowledgeBase/_engine
source .venv/bin/activate

# Smoke-test the index: should show all banks + thousands of docs
python3 run.py --status

# Then catch up on anything filed since the snapshot
python3 run.py --mode daily --verbose
```

## 6. Convenience: the `kb` shell alias

The everyday entry-point is `_scheduler/refresh.sh`. Aliasing it once means
you can run it from any directory.

```bash
# zsh (macOS default since Catalina)
echo "alias kb='~/Documents/RWork/Banking_Data/KnowledgeBase/_engine/_scheduler/refresh.sh'" >> ~/.zshrc
source ~/.zshrc
```

Then:

```bash
kb                                                # daily, all banks
kb --bank Axis_Bank                               # one bank
kb --mode backfill --bank Yes_Bank                # backfill one bank
kb --status                                       # show last run + corpus stats
```

## 7. (Optional) Re-enable the daily LaunchAgent

The engine ships with the LaunchAgent **off by default** — you have to
explicitly install it. If you want the same unattended 08:30 Mon–Fri
refresh you had on the old Mac:

```bash
cd ~/Documents/RWork/Banking_Data/KnowledgeBase/_engine/_scheduler
./install.sh                                       # 08:30 Mon-Fri default
# ./install.sh --time 07:15                         # custom time
# ./install.sh --python /opt/homebrew/bin/python3   # custom python
./status.sh                                        # confirm 'loaded: yes'
```

Grant **Full Disk Access** to both `/bin/bash` and the Python binary the
LaunchAgent uses, otherwise the agent fires but can't read files under
`~/Documents` (this is the #1 first-run problem on macOS):

> System Settings → Privacy & Security → Full Disk Access →
> add `/bin/bash` and your `.venv/bin/python3` (or wherever
> `install.sh --python` points to).

To turn it back off later:

```bash
./uninstall.sh
```

---

## 8. (Optional) Re-enable the Cowork chat summary

The Cowork scheduled task `banking-kb-daily-refresh` is currently disabled
in the source-of-truth (see `_scheduler/cowork_report_prompt.md`). If you
want a daily chat summary of the latest run log:

1. Open Cursor → Cowork Scheduled sidebar.
2. Find / re-import the task from `_scheduler/cowork_report_prompt.md`.
3. Set `enabled: true`.

It's read-only — it never runs the engine itself, only summarizes the
latest `_logs/run_*.json`. Re-enabling it without also installing the
LaunchAgent (or running `refresh.sh` regularly) will produce `STALE`
reports.

## 9. Verification — confirm the engine is healthy

Run all of these. None should error.

```bash
cd ~/Documents/RWork/Banking_Data/KnowledgeBase/_engine
source .venv/bin/activate

# 1. Engine sees its index + can summarize the corpus
python3 run.py --status

# 2. Search works end-to-end
python3 query.py "digital banking OR generative AI" --limit 5

# 3. Daily mode is a clean no-op against an already-fresh corpus
#    (should print 'new_downloads=0' for every bank if you just backfilled)
python3 run.py --mode daily --verbose

# 4. The scheduler entry-point works
./_scheduler/refresh.sh --status

# 5. (Only if you installed the LaunchAgent in step 7)
./_scheduler/status.sh                            # 'loaded: yes'
```

Expected `--status` output looks roughly like:


## 10. Things that commonly go wrong (and the fix)

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ModuleNotFoundError: requests` | venv not activated, or `requirements.txt` wasn't installed into the active interpreter | `source .venv/bin/activate && pip install -r requirements.txt` |
| `playwright._impl._errors.Error: Executable doesn't exist at .../chromium/...` | Step 3 was skipped or only `pip install playwright` was run | `python3 -m playwright install chromium` |
| LaunchAgent loads but the engine never runs (`status.sh` shows the agent loaded, but `_logs/` doesn't get new files) | `/bin/bash` or `python3` lacks Full Disk Access — they silently fail to read files under `~/Documents` | System Settings → Privacy & Security → Full Disk Access → add both binaries; then `launchctl kickstart -k gui/$(id -u)/com.rahul.banking-kb-daily-refresh` |
| `Permission denied: refresh.sh` | git on macOS sometimes drops the execute bit on clone (esp. via SMB / iCloud Drive) | `chmod +x _scheduler/*.sh` |
| Engine downloads PDFs but they all land in `<Bank>/<type>/undated/` | `dateutil` missing in the active venv, or `requirements.txt` install was interrupted | `pip install -r requirements.txt --force-reinstall` |
| NSE discovery errors for every bank (`NSE: blocked` / `403`) | NSE rate-limited the new IP — they're aggressive against fresh UAs | Ignore; the engine falls through to IR-page scraping. Re-run in an hour. |
| Backfill finds 0 PDFs on JS-heavy banks (HDFC, ICICI, SBI, Axis) | Chromium isn't installed or sandbox profile is missing | `python3 -m playwright install chromium`; on Apple Silicon, ensure you didn't accidentally `pip install playwright` under an x86 Python via Rosetta |
| `sqlite3.OperationalError: database is locked` | The LaunchAgent and a manual `refresh.sh` raced each other on `kb_index.sqlite` | `refresh.sh` now refuses to race the LaunchAgent (see `_scheduler/refresh.sh:111`); if you see this, the agent is mid-run — either wait, or `launchctl stop com.rahul.banking-kb-daily-refresh` and re-run |

## 11. Decommissioning the old Mac (after migration is verified)

Only after step 9 passes on the new Mac:

```bash
# On the OLD Mac
cd ~/Documents/RWork/Banking_Data/KnowledgeBase/_engine/_scheduler

# 1. Stop and remove the LaunchAgent so it doesn't keep firing in parallel
./uninstall.sh

# 2. (Optional) Disable the Cowork task from the Cowork Scheduled sidebar
#    so two laptops aren't reporting the same corpus.

# 3. (Optional) Archive the old KnowledgeBase/ folder to a backup drive
#    before wiping — you may want the historical _logs/ for audit later.
```

## TL;DR — minimum-viable rebuild on a new Mac

If you trust this list and want the 60-second copy-paste:

```bash
# Prereqs (skip lines you already have)
xcode-select --install
brew install python@3.12 sqlite

# Clone and stand up
mkdir -p ~/Documents/RWork/Banking_Data/KnowledgeBase
cd       ~/Documents/RWork/Banking_Data/KnowledgeBase
git clone <your-repo-url> _engine
cd _engine
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m playwright install chromium
python3 run.py --sync-structure

# Populate corpus (multi-hour)
caffeinate -is python3 run.py --mode backfill --verbose

# Verify
python3 run.py --status
python3 query.py "digital banking" --limit 3

# Quality-of-life
echo "alias kb='$(pwd)/_scheduler/refresh.sh'" >> ~/.zshrc
```

You're done.
